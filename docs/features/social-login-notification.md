# 상세 기획 및 설계: 소셜 로그인 연동 및 맞춤형 퀴즈 알림 시스템

## 1. 개요
본 문서는 '럭키보카' 서비스의 사용자 편의성 증대와 재방문 유도를 위한 소셜 로그인 연동 및 개인화된 알림 시스템의 상세 설계를 다룹니다.

---

## 2. 과업 1: 소셜 로그인 연동 (카카오/지메일)

### 2.1. 설계 목표
- OAuth2 프로토콜을 활용하여 사용자가 별도의 가입 절차 없이 카카오 및 구글 계정으로 간편하게 로그인할 수 있도록 함.
- 기존 이메일 가입 유저와의 계정 통합을 지원하여 데이터 파편화를 방지함.

### 2.2. OAuth2 흐름 (Authorization Code Grant)
1. **Frontend**: 사용자가 '카카오로 시작하기' 또는 '구글로 시작하기' 클릭.
2. **Backend**: 각 Provider의 인가 엔드포인트로 리다이렉트 (Client ID, Redirect URI 포함).
3. **Provider**: 사용자 인증 및 권한 동의 후 Redirect URI로 Authorization Code 전달.
4. **Backend**: 전달받은 Code로 Access Token 요청 및 사용자 정보(이메일, 프로필 등) 획득.
5. **Backend**: 획득한 정보를 바탕으로 회원가입 처리 또는 로그인 처리 후 JWT 발급.

### 2.3. 계정 통합 및 관리 전략
- **통합 기준**: `email` 필드를 유니크 식별자로 사용.
- **상황별 처리**:
    - **케이스 1 (신규 유저)**: 소셜 정보로 신규 계정 생성. `provider` 및 `providerId` 저장.
    - **케이스 2 (기존 로컬 가입자)**: 동일한 이메일로 소셜 로그인 시도 시, 기존 계정에 소셜 연동 정보를 업데이트하고 로그인 처리.
    - **케이스 3 (타 소셜 가입자)**: 동일한 이메일로 다른 소셜 로그인 시도 시, 연동 정보 추가(Multi-provider 지원 여부에 따라 결정, 초기에는 1:1 매핑 권장).

### 2.4. DB 변경 사항 (`users` 테이블)
- `provider`: `LOCAL`, `KAKAO`, `GOOGLE` (ENUM)
- `provider_id`: 소셜 서비스에서 제공하는 고유 식별값 (String)

## 3. 과업 2: 맞춤형 퀴즈 알림 시스템

### 3.1. 설계 목표
- 사용자가 원하는 시간에 퀴즈 알림을 받을 수 있도록 하여 학습 참여도를 제고함.
- 퀴즈 마감 전 리마인드를 통해 유저의 목표 달성을 지원함.

### 3.2. 주요 기능
1. **회원가입 시 설정**: 알림 희망 시간(HH:mm)을 입력받음. (기본값 제공 가능)
2. **고정 시간 알림**: 사용자가 설정한 시간에 매일 메일 발송.
3. **마감 임박 알림**: 매일 오후 11시(자정 1시간 전)에 당일 퀴즈 미참여 유저에게 리마인드 발송.
4. **설정 관리**: 마이페이지에서 알림 시간 수정 및 수신 여부(ON/OFF) 토글.

### 3.3. DB 변경 사항 (`users` 테이블)
- `notification_time`: 알림 희망 시간 (LocalTime, HH:mm)
- `notification_enabled`: 알림 수신 여부 (boolean, 기본값 true)

### 3.4. 알림 엔진 구조 (기술 설계)
- **Scheduler**: Spring `@Scheduled`를 사용하여 주기적으로 알림 대상자 추출.
    - `0 * * * * *` (매 분 실행): 현재 시간과 `notification_time`이 일치하는 유저 탐색.
    - `0 0 23 * * *` (매일 23시 실행): 마감 임박 알림 대상자(미참여자) 탐색.
- **Mail Engine**: `JavaMailSender`를 활용하여 이메일 발송.
- **비동기 처리**: 알림 발송량이 많을 경우 `@Async`를 사용하여 발송 로직을 별도 스레드에서 처리.

---

## 4. API 설계

### 4.1. Auth API
- `POST /api/auth/social-login`: 소셜 Access Token(또는 Code)을 받아 로그인을 처리하고 JWT 반환.
- `POST /api/auth/signup`: 기존 회원가입 요청에 `notificationTime` 필드 추가.

### 4.2. User API (마이페이지)
- `PATCH /api/users/notification`: 알림 시간 및 수신 여부 수정.
    - Request Body: `{ "notificationTime": "09:00", "notificationEnabled": true }`
